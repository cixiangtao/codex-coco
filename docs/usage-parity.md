# 用量行为对照与修复

2026-10-21，IKUN同学实际测试指出菜单栏图标在不同背景下显示异常、每日用量信息缺失、账号信息缺失。本次重新按旧仓库的行为核对，不把“有入口”或受控流程通过视为完整迁移。

对照基线：codex-usage `b33578383a35b0f9d5d67fc67fbf98309b7702f5`。参考 DashboardViewModel.swift、CodexUsageProvider.swift、Models.swift、CodexUsageApp.swift、StatusBarController.swift 和 CodexIntelligenceCheck.swift；旧仓库只读。许可与差异见根目录 THIRD_PARTY_NOTICES.md。

生产构建另修复继承 ELECTRON_RENDERER_URL 时误连开发服务、无法打开窗口的问题。开发 URL 只在开发构建生效；正式构建固定使用本地 app 协议。

## 验证口径

`pnpm run check` 验证合同、类型、边界与构建。`pnpm run verify:usage-parity` 在真实 Electron 中使用受控 CLI 与临时本地记录，连续验证刷新、7/14/30 天切换、辅助操作、取消、新窗口、速览、切换数据目录和原生图标属性。既有额度、通知、本地索引、重置卡、样本工具与系统菜单栏回归仍单独执行。

图标验证确认原生模板渲染合同及主题变化后的属性，不等于所有壁纸、显示器和系统辅助设置的视觉实测。没有真实模型调用、真实兑换、真实 CLI 更新、登录项修改或旧仓库修改。

## 尚未对齐

- 检测尚未自动读取 Codex 配置中的默认模型/推理强度；当前明确使用所选模型或 CLI 内置默认模型，并保持隔离执行。
- 检测已有逐样本推理计数、耗时和历史 TPS，但尚缺旧项目的平均推理计数、历史基线比较和差值呈现。
- 原项目浮窗可以直接发起业务刷新；Codex Coco 目前保留已经确定的跨模块只读速览边界，业务刷新仍在主窗口。快捷刷新权限和交互需要作为后续明确产品调整处理。
- 原项目通知/刷新默认开启；Codex Coco 默认停用，启用后启动读取一次，定时刷新和通知仍需分别开启。

上述差异明确保留为待办或产品约定，不能全部归类为“只差真实账号验收”。后续继续按旧项目逐项核对，不宣称本批已经完成 usage 全量等价。
