# Codex Coco UI 组件包与主题方案

日期：2026-10-21。状态：独立 UI 包、共享组件、根主题 Provider 和应用偏好适配已实现；下文同时包含已落地合同与后续扩展目标。

UI 组件独立到 `packages/ui`，桌面应用位于 `apps/desktop`，采用 pnpm workspace。组件包提供 Tailwind CSS + shadcn/ui 基础控件、可复用组合、语义 token 和主题能力；业务模块仍在桌面应用内组织。

这里的主题指 **Codex Coco 自身的 UI 主题**。对外部 Codex 的背景、布景和注入配置继续由外观业务模块负责，两套设置独立。

## 仓库与依赖边界

```text
apps/
  desktop/
    src/
      desktop/             Electron 主进程、preload 与系统适配
      application/         模块管理、配置、任务与诊断
      contracts/           应用级纯数据合同
      renderer/
        shell/             窗口布局与导航
        theme/             主题设置与共享 UI 包的应用适配
        client/            类型化桌面调用
      modules/             各业务模块的合同、运行时与页面
packages/
  ui/
    src/
      components/          shadcn/ui 基础控件与通用组合
      hooks/               不依赖桌面宿主的界面 hooks
      lib/                 cn 等界面工具
      theme/               主题类型、解析、预设、Provider
      styles/              语义变量、Tailwind 映射与基础样式
    components.json
    package.json
pnpm-workspace.yaml
pnpm-lock.yaml
```

包名采用 `@codex-coco/ui`，保持 `private: true`，应用通过 `workspace:*` 依赖。根目录统一管理 pnpm、Oxfmt 与检查命令。业务模块暂不拆成 workspace 包，不引入额外任务编排器或独立发布流程。

`packages/ui` 不导入 Electron、Node.js、IPC 客户端、业务模块或应用设置服务。React 和 React DOM 通过 peerDependencies 与应用统一，避免捆绑重复实例。应用通过公开的组件、主题和样式子路径导入，不跨目录引用包内私有文件。

首期在 workspace 内直接消费组件源码，由桌面渲染器构建，不单独发布或打包 UI 库。组件包拥有独立类型检查和组件合同测试，整体构建与打包仍需验证实际消费结果。该组织方式参考 [shadcn/ui workspace 文档](https://ui.shadcn.com/docs/monorepo)。

## 组件和样式约定

按钮、输入、选择、弹层等基础控件归组件包；与额度、主题注入、账号等业务数据绑定的复合组件留在对应业务模块。无业务依赖且确实重复使用的组合，再提升到共享包。

组件采用语义类名和集中维护的变体。页面使用 className 组织布局；组件的颜色、状态和排版差异通过 token 与组件变体表达，避免每个页面重写样式。组件状态、键盘交互与可访问名称随源码一起维护。

公共主题变量只有一个定义入口，shadcn 的 components.json 指向共享包的样式与组件位置；桌面应用的配置把共享控件和工具映射到包导出。初始化时核对别名和文件落点，不用网站模板覆盖 Electron 工程。

Tailwind 构建必须显式覆盖共享组件包的源码。正式构建验证来自包内、仅在运行时显示的控件样式，不把开发模式正常当作扫描已配置正确；具体 source 注册方式按 [Tailwind 源文件检测文档](https://tailwindcss.com/docs/detecting-classes-in-source-files) 设置。

自定义颜色通过 CSS 变量应用，不拼接 `bg-${color}` 之类的动态 Tailwind 类名。样式框架与全局重置统一加载，避免应用与组件包分别导入造成重复覆盖。

## 主题状态与职责

主题将模式、预设和主色覆盖分开表示：

| 设置项        | 含义                                               |
| ------------- | -------------------------------------------------- |
| schemaVersion | 当前存于应用配置根级，表示主题等偏好的数据格式版本 |
| mode          | light、dark 或 system；切换配色不改写模式          |
| presetId      | 已注册的主题预设，每个预设具备浅色和深色 token     |
| primaryColor  | 自定义主色，空值表示采用预设主色                   |

当前提供中性（默认）、蓝色和紫色工程预设以验证机制，不构成正式产品配色承诺。整页视觉方向继续评审，不沿用已删除原型的绿色。首期自定义颜色覆盖主色系列，完整主题预设的结构可承载更多语义变量，后续不需要重写组件。

| 职责                                           | 归属             |
| ---------------------------------------------- | ---------------- |
| 主题类型、合法值、token 解析和控件消费         | packages/ui      |
| 受控 ThemeProvider、模式解析、主题作用域       | packages/ui      |
| 主题偏好的读写、迁移与多窗口同步               | 桌面应用配置服务 |
| 主题选择、颜色输入、预览、应用、取消和重置交互 | 桌面应用设置界面 |
| 启动时提供有效主题与匹配的宿主背景色           | 桌面应用启动流程 |

UI 包不自行选择 localStorage 或其他持久化位置。应用维护已保存偏好，界面草稿用于预览；取消恢复已保存主题。确认应用时由宿主校验并持久化，成功后再广播已保存版本。不把未保存的预览当成其他窗口的新偏好。

system 模式随系统外观变化；明确选择 light 或 dark 时保持用户选择。已保存主题适用于所有应用窗口，旧 revision 不覆盖新状态。窗口首次显示前应用有效主题，并设置匹配的原生窗口背景，避免启动时明暗闪烁。

## 语义 token 和自定义主题色

采用 CSS 变量保存语义值，再映射到 Tailwind 工具类，遵循 [shadcn/ui 主题机制](https://ui.shadcn.com/docs/theming)。至少覆盖：background、foreground、card、popover、primary、primary-foreground、accent、muted、border、input、ring，以及需要时的图表和导航语义。

自定义主色不能只替换按钮背景。解析器需要生成当前模式下可用的主色、对应文字、悬停/按下、选中底色与焦点 token，并校验最终前景背景组合。输入可以先限定为标准 HEX 色值，颜色输入控件与内部主题表示解耦。

错误、警告、成功状态保持各自语义，不随用户主色任意变色。主色与成功色相近时仍通过图标和文案区分用途。预设和自定义主色都覆盖禁用、选中、焦点和弹层状态。

非法输入或无法生成合格对比度的组合不覆盖最后有效主题；界面说明原因并允许恢复预设。普通正文至少满足 4.5:1 对比度，大字和需要识别的控件边界至少 3:1；不能只校验用户输入的原始颜色而忽略实际 token 组合。

主题默认作用于应用文档根节点，确保挂到 body 的 Dialog、Popover、Tooltip 和通知层继承同一套变量。独立预览区域需要主题作用域与对应 portal 容器，不能让预览弹层逃逸到全局主题。

## 基建验收

| 场景                 | 应有结果                                                             |
| -------------------- | -------------------------------------------------------------------- |
| 独立消费 UI 包       | 组件包不需要 Electron、凭据和业务配置；应用可通过公开导出使用        |
| 包内控件的生产构建   | 基础样式、交互状态与包内 Tailwind 类全部生效，不仅开发模式正常       |
| 浅色、深色、跟随系统 | 切换实时生效；跟随系统变化时只影响 system 模式                       |
| 切换预设与修改主色   | 全部相关组件统一变化，模式与预设保持独立，页面无硬编码主色           |
| 弹层和通知           | Dialog、Popover、Tooltip、Toast 与所在主题一致                       |
| 颜色边界             | 极浅、极深、高饱和和非法输入得到可读结果或明确反馈，不损坏已保存主题 |
| 预览、取消、重置     | 未保存修改不污染持久化和其他窗口，取消恢复，重置回到当前预设         |
| 重开应用与窗口       | 已保存偏好恢复，首屏与原生窗口背景一致；窗口之间同步且无旧事件覆盖   |
| 配置损坏或未来版本   | 保留原文件；使用明确的恢复路径，不静默覆盖用户偏好                   |
