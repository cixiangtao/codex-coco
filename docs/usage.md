# 用量模块

2026-10-22：已接入启用后启动读取、成功额度缓存与可选定时刷新。主窗口提供启用、手动刷新、取消与异常恢复；菜单栏展示同一份成功额度快照。外观三层布景核心已接入。

## 使用

1. 本机需要可运行的 Codex CLI，并通过 `codex login` 使用 ChatGPT 账号登录。
2. 在侧栏打开“用量”，点击“启用并读取用量”。也可以在模块管理中单独启用，后台会自动读取一次。
3. 成功后显示各额度组的窗口长度、剩余比例、已用比例、恢复时间和读取时间。菜单栏同步显示摘要。
4. 后续点击“刷新用量”或“重新读取”；等待期间可取消。“模块管理 → 用量 → 停用模块”停止读取并停用模块。

模块默认停用。启用或应用重启恢复已启用状态时，后台自动读取一次，无需先打开用量页或点击刷新。新开窗口共享同一后台状态，不重复读取。定时刷新间隔默认 0，表示启动读取后不轮询；主窗口“刷新、通知与菜单栏设置”可单独保存 30–3600 秒间隔。失败指数退避，最多一小时；恢复成功后回到配置间隔。宿主忙碌则延迟，不并发读取；启动前手动刷新会取代启动任务，取消后不会立即偷偷重试。窗口全部关闭后仍可运行；改回 0 停止定时轮询，停用或退出清理全部计时器。

通知默认关闭。开启后按最紧张的额度窗口判断提醒与严重阈值（默认剩余 20% / 5%），进入区间、严重升级、恢复和首次刷新失败时发起系统通知；连续相同状态不重复请求。系统通知不可用不影响读取。账号邮箱在后台转换为私有关联标识与公开脱敏标识，识别到账号切换后清空前次额度和提醒状态，避免跨账号发送恢复提醒；匿名账号关联与成功额度写入私有缓存，明确兑换时也为核对重试账号写入私有幂等记录；关联标识不进入公开结果或日志。

菜单栏可以选择主要/次要窗口和显示周期名称，始终保留完整 Codex Coco 名称；显示的百分比和只读浮窗共享公开快照，失败时隐藏旧值。

CLI 按 PATH 查找，再检查 `~/.local/bin`、`/opt/homebrew/bin` 和 `/usr/local/bin`。图形应用环境找不到命令时会显示固定提示；Codex Coco 不自动安装 CLI。读取的是 CLI 当前登录的 ChatGPT 订阅额度，不是 API Key 账单用量。

## 数据源与权限

采用 [官方 App Server 协议](https://learn.chatgpt.com/docs/app-server)，每次刷新启动一个短期 `codex app-server` stdio 连接，严格执行：

```text
initialize → initialized → account/read(refreshToken: false) → account/rateLimits/read
```

不启动会话、模型任务或登录流程，默认额度读取不发送重置额度、登出或邮件请求。重置卡仅由单独的明确兑换操作触发，见下文。Codex CLI 根据自己的配置管理凭据和登录生命周期；Codex Coco 不直接读取 auth.json、令牌或钥匙串，也不导入旧应用配置。

CLI stdout 只在后台解析，stderr 被排空并丢弃；原始响应、账号邮箱、令牌、路径和底层异常不进入页面或诊断。公开结果包含额度窗口、已脱敏的账号标识、已知套餐、数值余额、读取时间、来源标记和固定错误码。账号标识在后台脱敏后再进入主窗口与速览；完整邮箱和原始账号响应不向界面发送。

客户端只执行固定命令参数，不经 shell；页面和模块配置不接受命令路径、参数或网络地址。macOS 下为该子进程创建独立进程组，完成、取消或失败时只清理本次创建的进程组。先终止，250ms 后仍未结束则强制终止；收到 close 后才结算。读取期限 10 秒，额度与本地统计的宿主任务另有 60 秒截止与清理隔离，不把发出取消当作清理成功。

## 额度与新鲜度

- 优先读取 `rateLimitsByLimitId`，兼容缺少该字段时的单组 `rateLimits`；明确返回的空集合不回退到旧视图。
- `usedPercent` 是已用百分比，剩余按 `100 - usedPercent` 计算。未知字段不填成零，不把 primary/secondary 位置固定解释为 5 小时/7 天；窗口名称由真实时长决定。
- 恢复时间使用 Unix 秒转本地时间，缺失时明确显示未知。达到恢复时间不会自行把额度改为 100%，需要再次读取确认。
- 限制最多 20 组额度，每组两个窗口；整个 stdio 连接接收的数据累计最多 1 MiB。非法数值、结构或超限响应显示恢复提示，不作为正常额度。
- 主窗口记录超过 10 分钟或恢复时间已到时提示刷新。本地 30 秒时钟只更新显示，不触发源读取。菜单栏显示读取时间，并提示在主窗口刷新确认。

预期的读取失败以严格的公开结果返回，运行宿主仍可接受重试；任务取消、超时隔离等继续遵循通用生命周期。失败时主窗口先展示固定原因和恢复文案；上次成功记录默认折叠，并标注其可能属于此前登录，不代表当前账号状态。成功额度额外存入 `usage-snapshot.json`，以 CODEX_HOME 的哈希隔离来源，文件权限 0600，原子替换。仅保存已经脱敏的账号、套餐、额度和读取时间；不保存令牌、模型回答、重置卡引用或兑换反馈。重启先恢复历史额度并展示读取时间和“非当前账号状态”提示，再读取当前额度；菜单栏在验证前不显示历史额度数值。失败不覆盖成功缓存；缓存损坏、超过 256 KiB、未来时间、超过 7 天或来源不同均忽略。切换本地目录会清除历史缓存。每日统计在本次刷新后重新扫描，不从磁盘额度缓存恢复，避免跨日冒充今日统计。

## 主窗口与菜单栏

用量页面独立注册，主窗口通过通用页面入口加载。模块管理负责启停和配置恢复，不重复嵌入主要业务页面。

2026-10-22 起采用已认可的柔彩仪表方向。总览集中展示额度圆环、脱敏账号与套餐、今日/近 7 天/近 30 天统计及每日趋势；“辅助工具”承载样本、CLI 维护与重置卡，“用量设置”承载刷新和通知偏好。标签页保持挂载，保留草稿且切换不触发业务操作。数据来源、扫描/目录维护与每日明细通过展开面板进入。Card/Box 等基线见 [UI 组件包](ui-package-and-theme.md)，样稿与实现边界见 [界面说明](surfaces/usage-and-glance.md)。

圆环只接受经过验证的剩余比例，未知与真实 0 区别展示；历史额度采用中性表面且不播放数值更新动画。趋势柱与日期使用同列网格，7/14/30 天切换只改变展示范围，完整 30 天摘要不受影响。小窗口允许纵向滚动。

模块通过 `BuiltinModule.glance` 声明公开摘要，宿主对说明、展示阶段、指标 ID/标签/值/说明及读取时间做严格结构与大小校验。菜单栏不接收完整操作结果、历史额度、模块配置或账号响应。读取中、取消或失败时不继续展示旧额度；失败摘要优先排序，跳转用量页恢复。模块配置或运行时异常仍跳转模块管理。

菜单栏的“刷新速览”只重新读取宿主摘要，不发起额度请求。速览窗口直接调用用量操作仍会被主进程拒绝，不能通过修改 DOM 身份绕过。

## 验证

`pnpm run verify:usage` 在临时 PATH 中放置受控 stdio 服务，验证真实生产 Electron 的完整流程；打包回归使用相同方式验证真实应用。受控服务只用于测试，不存在运行时示例开关或替代真实账号的默认数据。

覆盖首次启用、两种额度窗口、跨窗口共享而不重复读取、只读速览权限、错误优先与旧数据折叠、重新读取恢复、未登录、取消、退出清理、重启自动读取与缓存标识、明暗主题和 720×640。合同测试另覆盖非法/超大/分块响应、CLI 缺失与异常、超时、强制终止、输入白名单和摘要隐私。

额外使用已安装的真实 CLI，在独立空 CODEX_HOME、文件凭据存储及临时工作目录中验证初始化与未登录状态；没有调用真实账号的额度接口。该检查证明本机 CLI 的基础协议兼容，不等于真实账号端到端验收。

多账号管理、重置卡、模型检测等完整二期能力仍在实现。后续接入时继续区分服务记录、旧数据与当前状态，不把读取接口视为已完成全部用量能力。

`pnpm run verify:usage-policy` 使用临时受控 CLI，在真实 Electron 中拦截该次测试的通知 show 请求，验证状态转换、去重及隐私；启用 30 秒策略后关闭全部主窗口，确认后台自动读取并可重开看到结果。没有发送真实系统通知、没有读取真实账号。定时、退避、停用与配置验证另有合同测试。

## 本机记录与趋势

配置 v3 增加默认关闭的本地额度回退及 7/14/30 天统计范围。主窗口“扫描本机用量”明确读取 CODEX_HOME（默认 ~/.codex）下的 sessions 和 archived_sessions。可通过系统目录选择器另选记录根目录，私有路径保存在 usage-local/source.json，不进入模块配置、IPC 结果或诊断；取消选择不触发扫描。损坏的源设置报告失败，不静默改扫默认目录。

扫描在独立 usage-worker 中执行，只提取 session_meta 身份关系与 token_count 数值，原始消息与对话不写入索引。索引保存文件身份、完整行偏移、头尾边界指纹、匿名账号关联与结构化计数。追加只读取新完整行；截断、替换和边界变化触发重建；同一 session 的归档副本、重复事件和 fork 继承前缀去重。初始累计值优先使用 last_token_usage，之后使用累计差值，计数重置回退到当前 last 值。

结果在内存缓存十分钟，可显式重建。索引按 home 哈希区分，原子写入独立 usage-local/index，最多 32 MiB；最多 20,000 文件、200,000 个近期计数记录、单行 1 MiB，超限、文件不可读或缓存失败标记统计不完整。只统计所选本地日期范围；已知其他账号事件排除，无法归属事件仍明确列出。无法关联当前账号时不冒充账号级用量。

没有可用 JSONL 事件时，通过 node:sqlite 只读 state_5.sqlite 的 threads.created_at 与 tokens_used。该分布按线程创建日期归集累计 tokens，不能当作实际每日消耗；不与 JSONL 同时相加。无计数时显示缺少记录，不把未知用量说成真实零。

只有用户开启“服务失败时使用本地额度记录”，额度请求失败后才自动扫描本机回退；本机额度保留原事件时间，主窗口默认收起，并保留服务失败提示；菜单栏隐藏历史数值。趋势失败、取消和超时均遵循宿主任务与 worker 实际退出合同，禁止主线程同步扫描回退。

`pnpm run verify:local-usage` 使用临时记录目录、临时 CLI 和正式 Electron worker，验证计数、显式回退、原始元数据排除、历史折叠与菜单栏错误优先。合同测试覆盖追加半行、重写截断、继承/归档去重、账号过滤、超长/损坏记录、符号链接跳过、只读 SQLite 及真实 Node worker 退出。

## 重置卡

通过官方 account/rateLimits/read 读取可用数量与可选到期详情，保留 availableCount 的权威含义（详情可以为 null 或被服务截断）。只展示公开数量、到期时间与本地哈希引用，服务的原始 ID、标题和说明不进入 IPC。只有卡信息而无额度窗口时仍可显示，不用缺失额度冒充零。通知开启后，对 24 小时内到期的卡去重提醒。

“兑换”先弹出明确消耗说明，确认才调用 account/rateLimitResetCredit/consume。后台重新读取账号与卡列表，核对引用和匿名账号关联；发送前将逻辑请求 UUID、私有卡 ID、账号关联与 pending 状态原子保存到 usage-reset-attempts.json（0600）。同账号还有不确定请求时拒绝另发一个新请求；取消或网络中断保留 pending，可通过“检查上次兑换”恢复，并沿用同一幂等键重试。

服务 reset/alreadyRedeemed 均按幂等成功处理，随后重新读取额度，不推断额度已满；nothingToReset/noCredit 显示对应结果。账号改变拒绝重用旧请求。最多保留 30 条，优先清理已结束记录，不丢弃未确认请求；存储损坏时保留原文件并拒绝发起消费。此存储只为明确兑换操作，不保存登录令牌。

verify:usage-reset 在临时受控服务中验证取消确认无消费、服务已消费但响应失败、重启恢复和同键重试、额度重读及私有字段排除。合同测试另覆盖在途取消、过期引用、不同账号、终态重复请求和到期通知。未向真实账号发出兑换请求。

## 样本检测与 CLI 维护

主窗口展开“样本检测与 CLI 维护”，可明确读取分页模型列表、选择支持的推理强度、运行 1–5 个固定糖果题样本、读取和备份清空历史。模型与强度来自官方 model/list，不硬编码账号可用模型；无登录或 API Key 模式也可尝试 CLI 提供的模型目录。检测和 CLI 更新都需界面确认，额度刷新、启动或页面切换不会自动运行它们。

样本通过 codex exec 的临时会话执行，每个最多 120 秒，使用临时工作目录、read-only、ignore-user-config、ignore-rules、project_doc_max_bytes=0，关闭执行、应用、浏览器、记忆和相关宿主工具。固定问题通过 stdin 提供，答案用 output-schema 限定为 answer 整数与 explanation；原始 stdout/stderr 和底层错误不传到页面。只评价结构化 answer 是否为 21，不通过解释文本中碰巧出现的数字判断。该基准已用独立动态规划穷举 29,340 个可达状态，核对在可按形状选择并观察后继续选择的条件下最少保证数为 21。

检测显示完成/正确次数、耗时、输入/输出/推理 tokens，保留至多 100 条摘要历史与平均输出速度；缺失计数为未知，不填零。答案说明只在主窗口的临时结果中显示，不写摘要历史、诊断或菜单栏。命令失败不计为错误答案；少量样本不能证明整体模型能力变化。取消或停用会终止本次进程组，等待实际退出后结算，不登记伪完成结果。

CLI 维护读取已安装 codex --version，识别独立、包管理器或 Homebrew 安装（路径只在后台使用），并从固定官方 GitHub Release API 检查稳定版本。明确确认后调用已安装 CLI 自带 update，非交互运行，重新读取版本；已知目标版本时核对是否达到目标，再更新模型列表。不会在后台自动安装 CLI、运行网络 shell 脚本或修改当前项目的包管理器。

verify:usage-tools 使用受控 CLI、版本与发布响应，在真实 Electron 验证分页模型、强度、确认前无样本请求、结构化样本、摘要历史、受控升级和取消退出。合同测试另覆盖错误答案、命令失败、拒绝异常模型和损坏历史保护。历史损坏时不会开始消耗模型额度，须明确备份清空后再运行。本轮未调用真实模型，也未升级真实 CLI；旧版本 CLI 缺少隔离参数时明确失败，不回退到更宽松的执行方式。

## 2026-10-21 用量对照修复

- 数据与最近一次任务独立保存。读取模型、检查 CLI、扫描趋势、失败或取消辅助任务不再擦除额度、账号和已有趋势；已完成的样本在取消时保留摘要历史。该状态在当前进程的主窗口之间共享，停用后清理；没有承诺恢复旧项目的磁盘额度快照。
- 成功刷新额度后在 worker 更新近 30 天本地计数，手动刷新绕过十分钟内存缓存，但继续复用增量索引。图表按 7/14/30 天即时切片，今日、近 7 天与近 30 天摘要使用完整 30 天数据。缓存跨本地零点失效。
- 独立模型额度事件中的 token_count 继续纳入趋势，只排除其作为通用历史额度的回退。索引版本提升为 2，自动重建旧的漏计索引。
- 主窗口和速览显示脱敏账号、套餐及统计摘要；主窗口另显示服务返回的额外余额。菜单栏 5h/7d 依据窗口实际时长匹配，时长未知才按位置兼容。
- 选择 Codex 数据目录统一影响额度、重置卡、模型、CLI 工具和本地统计。目录只在私有 source.json 保存，不经 IPC 返回；切换后清空前一目录的额度和趋势，下一次操作重新读取。不接受无 Codex 数据标记的目录。
- 服务读取失败继续优先显示错误、收起旧额度；辅助任务失败不会把正常额度误报为服务不可用。速览仍只读，不会从速览触发账号刷新。
- 对照来源、已修内容与尚未补齐的行为见 [用量对照记录](usage-parity.md)。
