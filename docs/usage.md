# 用量模块

2026-10-21：已接入按需读取和可选自动刷新。主窗口提供启用、手动刷新、取消与异常恢复；菜单栏展示同一份成功额度快照。外观三层布景核心已接入。

## 使用

1. 本机需要可运行的 Codex CLI，并通过 `codex login` 使用 ChatGPT 账号登录。
2. 在侧栏打开“用量”，点击“启用并读取用量”。也可以在模块管理中单独启用，之后再到用量页刷新。
3. 成功后显示各额度组的窗口长度、剩余比例、已用比例、恢复时间和读取时间。菜单栏同步显示摘要。
4. 后续点击“刷新用量”或“重新读取”；等待期间可取消。“模块管理 → 用量 → 停用模块”停止读取并停用模块。

模块默认停用，自动刷新间隔默认 0（手动）。启用、重启或新开窗口在默认策略下不读取账号。主窗口“刷新、通知与菜单栏设置”可保存 30–3600 秒的自动间隔，保存的 opt-in 策略在启用和重启后继续生效；首次等候完整间隔，不立即读取。失败指数退避，最多一小时；恢复成功后回到配置间隔。宿主忙碌则延迟，不并发读取。窗口全部关闭后仍可运行；改回 0、停用或退出会停止定时器。

通知默认关闭。开启后按最紧张的额度窗口判断提醒与严重阈值（默认剩余 20% / 5%），进入区间、严重升级、恢复和首次刷新失败时发起系统通知；连续相同状态不重复请求。系统通知不可用不影响读取。账号邮箱只在后台短暂转换为内存中的关联标识，识别到账号切换后清空前次额度和提醒状态，避免跨账号发送恢复提醒；该标识不持久化、不进入公开结果或日志。

菜单栏可以选择主要/次要窗口和显示周期名称，始终保留完整 Codex Coco 名称；显示的百分比和只读浮窗共享公开快照，失败时隐藏旧值。

CLI 按 PATH 查找，再检查 `~/.local/bin`、`/opt/homebrew/bin` 和 `/usr/local/bin`。图形应用环境找不到命令时会显示固定提示；Codex Coco 不自动安装 CLI。读取的是 CLI 当前登录的 ChatGPT 订阅额度，不是 API Key 账单用量。

## 数据源与权限

采用 [官方 App Server 协议](https://learn.chatgpt.com/docs/app-server)，每次刷新启动一个短期 `codex app-server` stdio 连接，严格执行：

```text
initialize → initialized → account/read(refreshToken: false) → account/rateLimits/read
```

不启动会话、模型任务或登录流程，不发送重置额度、登出或邮件通知请求。Codex CLI 根据自己的配置管理凭据和登录生命周期；Codex Coco 不直接读取 auth.json、令牌或钥匙串，也不导入旧应用配置。

CLI stdout 只在后台解析，stderr 被排空并丢弃；原始响应、账号邮箱、令牌、路径和底层异常不进入页面或诊断。公开结果只包含额度窗口、读取时间、来源标记和固定错误码。原始账号响应在后台用于判断 ChatGPT 登录及临时关联账号，不向界面发送邮箱。

客户端只执行固定命令参数，不经 shell；页面和模块配置不接受命令路径、参数或网络地址。macOS 下为该子进程创建独立进程组，完成、取消或失败时只清理本次创建的进程组。先终止，250ms 后仍未结束则强制终止；收到 close 后才结算。读取期限 10 秒，宿主任务另有 12 秒截止与清理隔离，不把发出取消当作清理成功。

## 额度与新鲜度

- 优先读取 `rateLimitsByLimitId`，兼容缺少该字段时的单组 `rateLimits`；明确返回的空集合不回退到旧视图。
- `usedPercent` 是已用百分比，剩余按 `100 - usedPercent` 计算。未知字段不填成零，不把 primary/secondary 位置固定解释为 5 小时/7 天；窗口名称由真实时长决定。
- 恢复时间使用 Unix 秒转本地时间，缺失时明确显示未知。达到恢复时间不会自行把额度改为 100%，需要再次读取确认。
- 限制最多 20 组额度，每组两个窗口；整个 stdio 连接接收的数据累计最多 1 MiB。非法数值、结构或超限响应显示恢复提示，不作为正常额度。
- 主窗口记录超过 10 分钟或恢复时间已到时提示刷新。本地 30 秒时钟只更新显示，不触发源读取。菜单栏显示读取时间，并提示在主窗口刷新确认。

预期的读取失败以严格的公开结果返回，运行宿主仍可接受重试；任务取消、超时隔离等继续遵循通用生命周期。失败时主窗口先展示固定原因和恢复文案；上次成功记录默认折叠，并标注其可能属于此前登录，不代表当前账号状态。缓存只在模块运行期保留，停用或重启后不保留历史额度。

## 主窗口与菜单栏

用量页面独立注册，主窗口通过通用页面入口加载。模块管理负责启停和配置恢复，不重复嵌入主要业务页面。

模块通过 `BuiltinModule.glance` 声明公开摘要，宿主对说明、展示阶段、指标 ID/标签/值/说明及读取时间做严格结构与大小校验。菜单栏不接收完整操作结果、历史额度、模块配置或账号响应。读取中、取消或失败时不继续展示旧额度；失败摘要优先排序，跳转用量页恢复。模块配置或运行时异常仍跳转模块管理。

菜单栏的“刷新速览”只重新读取宿主摘要，不发起额度请求。速览窗口直接调用用量操作仍会被主进程拒绝，不能通过修改 DOM 身份绕过。

## 验证

`pnpm run verify:usage` 在临时 PATH 中放置受控 stdio 服务，验证真实生产 Electron 的完整流程；打包回归使用相同方式验证真实应用。受控服务只用于测试，不存在运行时示例开关或替代真实账号的默认数据。

覆盖首次启用、两种额度窗口、跨窗口共享而不重复读取、只读速览权限、错误优先与旧数据折叠、重新读取恢复、未登录、取消、退出清理、重启不自动读取、明暗主题和 720×640。合同测试另覆盖非法/超大/分块响应、CLI 缺失与异常、超时、强制终止、输入白名单和摘要隐私。

额外使用已安装的真实 CLI，在独立空 CODEX_HOME、文件凭据存储及临时工作目录中验证初始化与未登录状态；没有调用真实账号的额度接口。该检查证明本机 CLI 的基础协议兼容，不等于真实账号端到端验收。

多账号管理、重置卡、模型检测等完整二期能力仍在实现。后续接入时继续区分服务记录、旧数据与当前状态，不把读取接口视为已完成全部用量能力。

`pnpm run verify:usage-policy` 使用临时受控 CLI，在真实 Electron 中拦截该次测试的通知 show 请求，验证状态转换、去重及隐私；启用 30 秒策略后关闭全部主窗口，确认后台自动读取并可重开看到结果。没有发送真实系统通知、没有读取真实账号。定时、退避、停用与配置验证另有合同测试。

## 本机记录与趋势

配置 v3 增加默认关闭的本地额度回退及 7/14/30 天统计范围。主窗口“扫描本机用量”明确读取 CODEX_HOME（默认 ~/.codex）下的 sessions 和 archived_sessions。可通过系统目录选择器另选记录根目录，私有路径保存在 usage-local/source.json，不进入模块配置、IPC 结果或诊断；取消选择不触发扫描。损坏的源设置报告失败，不静默改扫默认目录。

扫描在独立 usage-worker 中执行，只提取 session_meta 身份关系与 token_count 数值，原始消息与对话不写入索引。索引保存文件身份、完整行偏移、头尾边界指纹、匿名账号关联与结构化计数。追加只读取新完整行；截断、替换和边界变化触发重建；同一 session 的归档副本、重复事件和 fork 继承前缀去重。初始累计值优先使用 last_token_usage，之后使用累计差值，计数重置回退到当前 last 值。

结果在内存缓存十分钟，可显式重建。索引按 home 哈希区分，原子写入独立 usage-local/index，最多 32 MiB；最多 20,000 文件、200,000 个近期计数记录、单行 1 MiB，超限、文件不可读或缓存失败标记统计不完整。只统计所选本地日期范围；已知其他账号事件排除，无法归属事件仍明确列出。无法关联当前账号时不冒充账号级用量。

没有可用 JSONL 事件时，通过 node:sqlite 只读 state_5.sqlite 的 threads.created_at 与 tokens_used。该分布按线程创建日期归集累计 tokens，不能当作实际每日消耗；不与 JSONL 同时相加。无计数时显示缺少记录，不把未知用量说成真实零。

只有用户开启“服务失败时使用本地额度记录”，额度请求失败后才自动扫描本机回退；本机额度保留原事件时间，主窗口默认收起，并保留服务失败提示；菜单栏隐藏历史数值。趋势失败、取消和超时均遵循宿主任务与 worker 实际退出合同，禁止主线程同步扫描回退。

`pnpm run verify:local-usage` 使用临时记录目录、临时 CLI 和正式 Electron worker，验证计数、显式回退、原始元数据排除、历史折叠与菜单栏错误优先。合同测试覆盖追加半行、重写截断、继承/归档去重、账号过滤、超长/损坏记录、符号链接跳过、只读 SQLite 及真实 Node worker 退出。
