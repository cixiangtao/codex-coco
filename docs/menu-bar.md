# 菜单栏与跨模块速览

日期：2026-10-21。状态：原生菜单栏入口、只读悬浮窗和主窗口跳转已实现；用量已接入手动读取的公开额度，外观已接入连接与同步状态摘要。首期验证 macOS arm64。

## 使用方式

应用运行后，菜单栏默认显示完整名称 Codex Coco 和单色模块网格图标。启用“系统与菜单栏”后可选原生或自定义图标、GIF、逐图速度与按需 CPU 联动；停用清理动画和采样计时器。单击开合速览，右键菜单可打开主窗口、用量、外观、设置或退出。应用菜单中的“显示或收起速览”使用同一路径，并提供局部快捷键 Cmd+Shift+M。

速览失去焦点、按 Esc 或点击关闭图标时收起。关闭全部主窗口后，仍可从菜单栏进入；点击模块或设置入口，会复用最近聚焦的主窗口，必要时新建一个。窗口最小化时会恢复，主窗口中未保存的主题草稿保留。普通“打开主窗口”保留已有页面；没有主窗口时默认进入外观。

用量默认停用，明确读取后速览显示额度窗口、剩余比例、恢复时间和读取时间。读取中、取消和失败时不展示旧额度，失败优先并跳转用量页恢复。外观显示连接、同步与恢复状态。已注册模块加入阶段摘要，启停在模块管理中操作。刷新按钮只重新读取宿主摘要，不触发账号或网络更新。尚未提供摘要块选择设置或自定义业务指标。

## 结构与生命周期

`desktop/main/menu-bar.ts` 持有一个 Tray 和一个延迟创建的 360×420 悬浮窗。首次点击才创建渲染窗口，收起后复用；窗口被关闭或销毁后，下次打开重新创建。快速开合的意图在 renderer ready 前也有效，加载完成不会重新弹出已取消的窗口。没有常驻轮询。

`glance-bounds.ts` 使用 Electron 的 DIP 坐标，从菜单栏锚点和显示器 workArea 计算位置；支持负坐标显示器、底部任务栏和受限工作区，必要时缩小窗口。显示器移除或工作区变化时重新定位。

原生入口使用内嵌 2× PNG 模板图标，不依赖开发/打包路径，不构成正式应用 Logo。退出时销毁 Tray、注销屏幕监听，再沿用原有模块停止、配置与日志排空流程。Tray 创建失败时记录固定错误码，主窗口仍可运行，应用菜单保留速览入口。实现参考 [Electron Tray](https://www.electronjs.org/docs/latest/api/tray)。

## 窗口身份与权限

主进程按 webContents 注册 main / glance 身份，不从 URL、DOM 或调用参数推断角色。两个窗口使用相同受限入口，不增加任意 URL 路由。

| 能力                               | 主窗口 | 速览窗口 |
| ---------------------------------- | ------ | -------- |
| 读取窗口身份、已保存主题           | 允许   | 允许     |
| 获取完整模块快照、启停、配置和任务 | 允许   | 拒绝     |
| 保存主题、恢复设置                 | 允许   | 拒绝     |
| 读取/订阅速览摘要                  | 不提供 | 允许     |
| 跳转到既定主窗口页面               | 允许   | 允许     |
| 收起速览                           | 拒绝   | 允许     |

新增方法通过固定白名单通道暴露。跳转输入使用 strictObject，仅允许四个 MainPage，或空对象表示打开已有主窗口；不接受 URL、文件路径或额外字段。完整模块事件仅推送给主窗口，速览仅收到公开投影。沙箱、主 frame、精确入口地址、CSP、外部导航和权限拒绝规则继续有效。

## 摘要合同

`contracts/glance.ts` 定义 id、公开标题、展示阶段、说明、主窗口目标、有限指标与读取时间。模块通过 BuiltinModule.glance 声明公开字段，ModuleHost 使用 strictObject、长度与条数限制校验；`application/glance.ts` 合成状态，不复制完整配置、任务结果、任务名或原始错误。指标只含稳定 ID、标签、展示值和说明，最多 40 项。

未注册能力显示“尚未接入”。配置、运行时或任务生命周期异常优先，引导到模块管理；业务读取失败可使用模块自己的公开提示并回到主要页面。用量失败不向摘要发送历史额度或历史读取时间。接入合同见 [用量模块](usage.md)。

宿主为摘要维护独立单调 revision。仅展示内容变化时推送，任务的重复进度事件不会重复刷新相同摘要。客户端先订阅再读取，旧读取不能覆盖更新的事件；读取失败隐藏旧内容，提供重新读取和进入主窗口的入口。

速览只跟随已保存主题与系统明暗变化。主窗口未保存的预览不进入速览；保存后的广播才更新它。

## 验证与边界

- `pnpm run check`：58 个源码文件的 AST 边界、类型、10 个文件 84 项测试及生产构建。
- 新合同测试覆盖摘要隐私字段排除、异常优先、取消语义、严格跳转参数，以及负坐标、边缘和受限工作区定位。
- `pnpm run verify:menu-bar`：真实 Electron，延迟创建、权限与伪装身份、模块事件隔离、摘要状态变化、主题预览不泄漏、跨页草稿保留、保存同步、Esc/失焦、快速开合、销毁重建、无主窗口跳转、读取失败恢复和旧响应拒绝。
- `pnpm run verify:packaged`：重新打包并验证主窗口、速览、worker 资源与用量流程；示例开关仍被打包应用忽略，首次启动的用量为停用状态。
- `pnpm run verify:usage`：受控 stdio 服务驱动真实用量路径，确认摘要只含公开额度、失败隐藏旧值、速览无刷新账号的权限，主窗口重试后同步恢复。
- 原有 verify:desktop、verify:modules、verify:diagnostics 回归通过。

自动验证从原生应用菜单触发与 Tray 相同的开合回调，并确认原生 Tray 创建没有失败；没有使用鼠标自动点击系统状态栏。定位在本机显示器上运行，并用纯函数测试补充其他坐标情况，不等于所有硬件实测。截图位于忽略目录 `work/menu-bar-verification/`，全部测试使用临时数据并清理进程与目录。

用量读取由主窗口明确触发，通过本机 Codex CLI 管理登录；速览自身不读取账号。没有重新采样性能，之前的性能基线不代表新用量流程的数值。应用仍是本地未签名目录，未发布。
