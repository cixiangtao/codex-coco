## 真实桌面回归

生产文件与打包应用分别执行同一套 Playwright Electron 场景，使用临时 CODEX_COCO_DATA_DIR；结束后关闭应用并删除数据。

1. 检查真实启动窗口 980×800、生产协议、renderer 无 process/require，以及仅在 UI 包中定义的控件样式。
2. 浅色、深色、跟随系统切换；工程预设切换不改模式；系统变化只影响 system。Playwright 设置 colorScheme: null，避免其默认浅色模拟覆盖 Electron nativeTheme。
3. 自定义黑色/白色主色、非法输入保留最后有效主题、保存禁用和取消恢复。
4. 保存、Dialog 主题继承、Esc 关闭和焦点返回；第二窗口恢复保存值，当前预览不广播。
5. 其他窗口保存后，有草稿窗口保留预览并显示冲突；取消恢复最新版本；非法 IPC 输入与过期 revision 被拒绝。
6. 精确调整原窗口到 720×640，截图与横向溢出检查通过；主题核心控件在首屏，组件示例允许纵向滚动。
7. 外部导航被阻止；关闭全部窗口后通过应用激活重开，主题恢复；退出再启动也保留偏好。
8. 人为损坏临时配置，确认原文件未自动覆盖；点击恢复后产生原文备份，并恢复默认设置。

截图保存在忽略目录 work/desktop-verification/ 和 work/desktop-verification-packaged/，覆盖浅色、深色弹层与最小窗口。截图已实际查看，未发现横向溢出、主题核心控件遮挡或弹层不可读；这不代替用户的产品审美验收。机械 UI 检测未报告问题，也不等同完整可访问性审计。
