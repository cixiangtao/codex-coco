# 模块交互流程

2026-10-22：沿用已批准的柔彩仪表台和分组设置，先改善任务衔接、反馈位置与恢复入口。

## 共同规则

- 界面区分任务已受理、执行中、已完成、失败和取消。业务返回错误时不能把任务的 succeeded 当作业务成功。
- 用户发起的耗时操作通过 `ModuleOperationStatus` 在模块标签页外显示任务名称、进度、取消与失败恢复；使用固定操作名称，不展示原始错误或内部参数。用量读取继续使用原有专用工具栏；后台同步、预览、监测不制造持续提示。
- 任务执行时避免重复提交，取消等待实际任务停止。已保存配置和未保存草稿分开，失败不吞掉草稿。
- 外部应用重启、真实推理、更新、重置卡及系统登录项仍保留对应明确确认；检测、状态展示不代用户执行这些动作。

## 本轮落地

外观：检测当前应用是否带调试参数并验证实际端口；提供可理解的启动/重启/连接恢复入口。明确启动或重启成功后自动应用、验证已保存布景。悬浮面板允许专用受限快捷动作，重启原生确认，取消和并发变更不触发操作。主窗口保存、应用、撤销与验证等待结果后反馈。

用量：模块级任务反馈跨总览、工具与偏好标签可见，原本仅在总览显示的请求错误提升为页面级反馈。保留原有额度读取、取消和异常恢复语义，不增加真实账号读取源。

系统与菜单栏：检查系统、应用登录项和应用共享设置等待实际完成后展示结果。共用任务反馈与停止入口覆盖耗时操作；保存偏好与确认修改系统仍分开。

## 后续仍需逐项验收

本轮没有把所有模块重做一遍。模型检测、重置卡、更新安装、设置恢复及图库管理等完整操作仍需按具体任务继续评估入口、反馈和恢复链路；共用状态组件不能替代每项业务的完成判断。实际验证范围记录在 verification.md。
