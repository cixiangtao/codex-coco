# 应用更新

Codex Coco 使用按需加载的 electron-updater 6.8.9。应用更新属于应用宿主，生命周期持续到退出，不挂在某个业务模块下。用量的 CLI 升级是另一项明确操作，两者互不触发。

## 当前交付边界

仓库仍只保留本地，没有发布源、签名或公证。默认发布源为空、后台检查间隔为 0，启动不请求网络。当前开发运行和未签名安装目录会显示“需要签名的 macOS 安装版”，不会尝试替换自身。没有为这项功能创建远端、上传包或配置 Apple 账号。

自动替换使用 Electron/Squirrel 的 macOS 签名机制；需要正式签名的当前应用及相同发布者的更新包。参见 [Electron autoUpdater](https://www.electronjs.org/docs/latest/api/auto-updater)。当前本地包不能作为签名安装验收。

## 用户流程

1. 设置页填写可信发布者提供的 HTTPS 更新目录，以 `/` 结尾，不含凭据、查询参数或片段。保存采用 revision 冲突检查和原子写入。
2. 点击检查，仅读取版本元数据。可选 4–168 小时后台检查；0 保持手动。不会自动下载。
3. 发现版本后明确确认下载。更新引擎验证 SHA-512，显示下载进度；取消等待底层任务实际结束。检查的底层请求不支持即时中断，界面会保持等待取消。
4. 下载完成后再次确认安装并重启。原生安装器验证签名，再替换和重新打开。普通退出不会自动安装；界面不会把下载完成描述成签名安装成功。

更新源需提供 electron-builder 通用提供者支持的 `latest-mac.yml` 和对应架构的签名 ZIP，包含真实版本、文件 URL、字节数和 SHA-512。未来开放发行时由发布流程生成，不手写虚假散列或沿用旧项目发布源。

损坏配置不被静默覆盖；“重置更新设置”保留备份后恢复空源。已下载或正在安装时禁止更换源。更新包缓存由更新引擎管理，不保存账号凭据。更新引擎的持久 rollout UUID 被统一的请求头覆盖，不向发布源发送安装唯一标识。公开状态只含版本、进度、时间和固定错误码，不包含文件路径、发行说明或原始异常。主窗口可读写，速览连更新设置读取也不开放。

## 验证

- 合同测试使用受控更新引擎，验证显式下载/安装、取消结算、定时 opt-in、配置冲突、损坏备份、未签名边界与原始错误排除。
- `pnpm run verify:updates` 及打包版验证真实主窗口、跨窗口、重启、恢复和速览拒绝读写；测试源为无效示例域名，未签名检查在请求网络前阻止，未执行真实安装。
- 下载完整性由固定版本更新引擎实现，真实签名 ZIP 的下载、系统签名校验、替换和重启仍需未来发布源与签名包验收。当前不声称这些已在真实发布环境通过。
